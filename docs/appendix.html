A. 术语表

术语 一句话解释
Agent 正在工作的助手：模型 + Harness + 当前上下文
Harness Agent 的工作台：工具、会话、权限、插件
Model 大脑：负责理解、推理、生成
Session 一次连续对话
Workspace Agent 工作的文件夹
Context Window 模型一次能处理的内容上限
Compaction 上下文快满时的压缩
Tool Agent 能执行的动作
Skill 教 Agent 怎么做的知识/流程
Preset 单个 Agent 的能力组合
Plugin 运行时能力扩展
Bundle 可安装的插件/配置补丁包
Profile 一套安装环境
Sandbox 限制文件/命令访问范围的机制
Approval 敏感操作前的确认
MCP 连接外部工具/数据的协议
PTC 用代码组织工具调用的模式
Creator 扩展 DSH 的 Preset（内部 id cordis）

B. 10 个提示词模板

1. 只读盘点

请只读当前工作区，列出文件并按类型分组。
不要修改任何文件，也不要运行会改变文件的命令。
最后说明你用了哪些工具。

2. 先计划

先不要执行。请给我一个 3–5 步计划：
每步做什么、读/写哪些文件、怎么验证。
我确认后你再开始。

3. 生成文档

请阅读 [文件列表]，生成 [输出文件]。
要求：[结构/长度/语言/链接]。
不要修改原文件。
完成后检查输出文件是否存在，并列出你读过的文件。

4. 代码审查

请审查这次改动，优先找 bug、边界情况、测试缺口。
按严重程度排序，指出文件和行号。
先不要改代码，只给报告。

5. 调试

请先复现问题，再提出最多 3 个假设。
每次只验证一个假设，并给出证据。
不要在没有验证的情况下大改代码。

6. 资料调研

请调研 [主题]，优先使用一手来源。
输出：结论、证据链接、反方观点、仍不确定的地方。
不要编造来源。

7. 数据整理

请读取 [输入]，按 [字段] 整理成 [输出格式]。
不要修改原始数据。
先给我字段映射和清洗规则，确认后再执行。

8. 写作

请按 [读者/语气/长度/结构] 写一篇 [主题]。
不要使用空泛套话；每个观点要有依据。
先给提纲，确认后再写全文。

9. 文件整理

请先只读列出 [目录] 的文件，给出整理方案。
不要删除/移动任何文件，等我确认。
方案要说明每个文件去哪、为什么。

10. 插件需求

我想给 DSH 加一个能力：[描述]。
先不要写代码。请检查：
1. 应该挂在哪一层；
2. 需要哪些 API/模板；
3. 最小版本是什么；
4. 怎么验证、怎么卸载。

C. 开始任务前的检查清单

[ ] 目标一句话说清楚了吗？
[ ] 输入文件/目录明确了吗？
[ ] 输出位置和格式明确了吗？
[ ] 有哪些禁止事项？
[ ] 怎么验收？
[ ] 需要备份/提交吗？
[ ] 是否需要只读先行？
[ ] 是否涉及密钥/隐私？
[ ] 是否需要安装插件/开高权限？

D. 任务完成检查清单

[ ] 输出文件真的存在吗？
[ ] 内容符合要求吗？
[ ] 原文件有没有被改？
[ ] 有没有遗漏输入？
[ ] 有没有编造事实/来源？
[ ] 有没有测试/验证证据？
[ ] 需要交付的文件 present 了吗？
[ ] 临时文件清理了吗？
[ ] 需要回滚时知道怎么做吗？

结语

DSH 不难用，难的是在它变强之前，先学会控制它。

记住三句话：

  1. 先只读，再写入。
  2. 先小步，再扩大。
  3. 密钥不进对话，破坏性操作先备份。

当你熟悉了这些，再去碰 Preset、Plugin、Bundle、Creator。那时你看到的不再是一堆名词，而是一套可以按需组合的工作台。
