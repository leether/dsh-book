四篇，不是四个难度等级

这套书按研究对象分篇，而不是按“简单 / 中等 / 难”分：

  • 入门篇：使用 DSH；
  • 进阶篇：在 DSH 上设计插件；
  • 深入篇：设计 DSH 本身；
  • 认知篇：我们为什么这样设计、这样取舍。

现阶段用“篇”，不急着用“卷”。

篇是阅读结构，卷是出版承诺。
篇可以生长，可以留占位；卷必须能独立站住。

进阶篇：插件设计

状态：规划中 · 先写插件设计

这一篇讨论“怎么把一个能力做成可靠的 DSH 插件”，重点不是 API 清单，而是契约、边界、测试和发布。

这一篇要回答

  • 什么时候值得做一个 Tool，什么时候应该留给 CLI 或 Skill；
  • 参数、返回、错误和副作用怎么设计；
  • 删除、覆盖、权限和确认怎么做；
  • 怎么用假 CLI 测试，怎么做真实验收；
  • 怎么打包、发版，并让版本差异可控。

  • Session、Context、Skill 和 UI 插槽是怎么组织的；
  • 哪些设计是稳定契约，哪些只是当前实现。

写作与更新规则

  1. 一次只写透一个章节；不为了凑目录写空章节。
  2. 占位只出现在本页的路线图里，不生成空白章节页。
  3. 每章标记状态：待写 / 待验证 / 草稿 / 已发布。
  4. 每章记录验证环境；DSH 版本变化后，相关结论要重新检查。
  5. 先把一篇写到能独立成立，再讨论升级为“卷”。
  6. 已发布的章节 URL 尽量保持不变；新增内容用新路径，避免破坏旧链接。

现在怎么读

  • 第一次用 DSH：从入门篇第 1 章开始；
  • 准备做插件：读完入门篇，进入进阶篇的契约、权限、测试；
  • 想理解内部机制：先读进阶篇，再读深入篇；
  • 想做判断：随时翻认知篇，不需要按顺序。

这套结构会继续长，但不会为了“看起来完整”而提前写满。
