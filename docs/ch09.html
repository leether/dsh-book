第 9 章　创造模式：从使用者到扩展者

约 4 分钟 · 1,993 字 · 10 个小节

本章你会学会

  • 创造模式到底是什么，不是什么；
  • 它比标准模式多了哪些能力；
  • 什么时候该用，什么时候不该用；
  • 一次完整的“做插件”流程；
  • 不会编程的人怎么参与；
  • 怎么避免把 DSH 改坏。

9.1 创造模式是什么

创造模式是 DSH 的一个 Agent Preset，内部 id 是 cordis。

它不是：

  • 另一个模型；
  • 另一套运行时；
  • 另一个软件；
  • 更聪明的标准模式。

它是：

在标准任务工具之上，额外提供运行时检查、插件管理、以及插件/Preset 开发指引的一种工作模式。

它和标准模式共用：

  • 同一个 Agent loop；
  • 同一个模型；
  • 同一个沙箱/权限系统；
  • 绝大部分任务工具。

差别只在“composition（插件组合）”。

9.2 它比标准模式多了什么

通常包括三类能力。

1. 运行时检查

可以查询 DSH 当前真实的：

  • Service 方法；
  • Config schema；
  • Tool schema；
  • Skill 列表；
  • 界面 Slot / theme token。

这解决了一个大问题：不用猜 API。

2. 插件管理

可以：

  • 列出已安装的 Bundle；
  • 安装/启用/停用/卸载；
  • 修改 profile 的插件选择；
  • 查看安装结果和警告。

这些操作会持久化到 profile，影响所有 Session，并在重启后保留。

3. 开发指引

创造模式会挂载一组 authoring Skill，告诉你：

  • 怎么写 Cordis 插件；
  • 怎么写 Bundle patch；
  • 怎么创建/覆盖 Preset；
  • 怎么验证插件真的生效。

它还会提供模板和参考资料，按需加载。

9.3 什么时候该用

适合：

  • 想给 DSH 加一个工具；
  • 想加一个界面/按钮/面板；
  • 想做一个自定义模式；
  • 想调试“插件为什么没加载”；
  • 想把自己的工作流封装成插件。

不适合：

  • 日常写代码；
  • 普通文件整理；
  • 只是想让 Agent 帮你查资料；
  • 你不需要扩展 DSH 的时候。

原因：

  • 多出的工具和 Skill 会占用上下文；
  • 插件安装是高风险操作；
  • 日常任务用标准模式更轻。

9.4 安全边界：这是高信任模式

创造模式可以做很多“普通模式不能做”的事，因为：

  • 安装插件会在 Host 进程执行代码；
  • 修改 profile 会影响所有 Session；
  • 插件可能读写文件、访问网络、运行命令；
  • 这些代码在 workspace sandbox 之外执行。

所以：

  • 插件管理通常需要 full access 或逐次审批；
  • 不要给不信任的代码 full access；
  • 先在测试 profile/工作区试；
  • 重要配置先备份；
  • 出问题要能停用/回滚。

创造模式不是“安全模式”，它是“高信任的扩展模式”。

9.5 一次完整的“做插件”流程

下面是一个通用流程，不要求你会写代码，但要求你能描述目标和验收。

第 1 步：描述能力

不要一上来就说“帮我写个插件”。先说清楚：

我想给 DSH 加一个能力：
- 它做什么；
- 在哪里使用（聊天/按钮/面板/工具）；
- 输入是什么；
- 输出是什么；
- 怎么验证它成功；
- 不需要做什么。

第 2 步：让它先检查

先不要写代码。
请用运行时检查工具，确认：
1. 这个能力应该挂在哪一层（Host 插件 / Preset 插件 / 纯配置）；
2. 可用的 Service / Slot / Tool API；
3. 是否需要新的 Bundle；
4. 有没有现成模板。
把结论和风险列给我。

第 3 步：做最小版本

先做一个最小可用版本。
不要做额外功能、不要做多个变体。
给出文件清单、安装方式、验证步骤。

第 4 步：安装并验证

安装到当前 profile。
安装后告诉我：
- 安装结果（applied / warnings）；
- 新增了哪些工具/Skill/界面；
- 怎么验证；
- 怎么卸载。

第 5 步：修复与迭代

只修观察到的问题，不要无限加功能。

第 6 步：收尾

请给出：
- 插件位置；
- 安装/卸载方式；
- 已验证的内容；
- 未验证的内容；
- 已知限制。

9.6 不会编程的人怎么参与

你不需要自己写代码，但你需要做三件事：

  1. 说清楚目标：用户是谁、在什么场景、输入输出是什么；
  2. 审查结果：它有没有做你没要求的事？有没有权限过大？
  3. 验收：按你定义的场景试一遍，不通过就具体反馈。

你可以要求：

不要只告诉我“完成了”。
请给出：
- 改了哪些文件；
- 新增了哪些能力；
- 我怎么手动验证；
- 如果失败，怎么回滚。

9.7 常见误区

  • “创造模式是高级版标准模式”：不是。它是扩展模式。
  • “装插件只是改配置”：不是。插件可能执行代码。
  • “装了就会自动生效”：不一定，可能需要重载/重启。
  • “Preset 可以当沙箱”：不可以。
  • “让 Agent 直接改 profile 文件”：不要，用 Plugin Manager。
  • “一次做很大”：先最小版本，再迭代。

马上试试

  1. 新建一个创造模式任务；
  2. 不要安装任何东西；
  3. 让它列出当前可用的运行时检查能力；
  4. 问它：“如果我要加一个只读工具，应该挂在哪一层？为什么？”
  5. 读它的回答，不执行。

小结

  • 创造模式是 cordis Preset，不是模型/运行时。
  • 它多出运行时检查、插件管理、开发指引。
  • 适合扩展 DSH，不适合日常任务。
  • 插件代码在 Host 执行，必须有信任和回滚方案。
  • 先最小版本，再验证、再迭代。
